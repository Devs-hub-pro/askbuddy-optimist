# Call v1（微信小程序）端侧实现说明

## 1) 小程序能力边界评估（语音优先、视频可选）

### 建议
- P0 主链路：语音通话（发起/接听/拒绝/挂断 + 麦克风权限）
- P1 可选：视频通话（在语音链路稳定后打开摄像头权限与视频视图）
- 端侧仅消费 A 主线契约，不新增字段/状态/RPC

### 小程序能力边界
- 可做：`wx.authorize`/`wx.getSetting` 权限申请、页面级状态渲染、前后台生命周期监听。
- 受限：
  - iOS 小程序后台长时保活弱，退后台后实时音视频稳定性有限；
  - 无系统级来电页（与原生 App 不同），需要应用内来电页/通知页承接；
  - 真实 WebRTC/VoIP 引擎能力与插件、机型、基础库版本相关，需要真机验证。

## 2) 现有入口页接入点清单

1. `pages/messages/index`
- 最自然入口：会话/通知场景发起语音或视频。
- 现已增加：`去通话联调页` 入口按钮。

2. `pages/question-detail/index`
- 可作为“向回答者发起咨询通话”入口（本轮未加业务按钮，仅保留扩展点）。

3. `pages/profile/index`
- 可作为权限预检查入口（麦克风/摄像头授权引导，后续可补）。

## 3) 最小联调壳层范围

- 页面：`pages/call/index`
- 动作：发起 / 接听 / 拒绝 / 挂断
- 权限：麦克风必须；视频模式额外摄像头权限
- 状态：`idle` / `dialing` / `ringing` / `connected` / `rejected` / `ended` / `failed`
- 契约策略：
  - 端侧通过 Call v1 适配层调用 A 契约映射；
  - 若映射未配置，明确报错 `A_CONTRACT_GAP`，不自行猜字段。

## 4) A 契约缺口提报（当前）

缺少 A 明确下发的以下内容：
1. Call v1 RPC 名称与入参 schema（发起/接听/拒绝/挂断）；
2. Call session 状态机字段与枚举；
3. 来电事件下发方式（轮询 / realtime / 推送桥接）；
4. 语音/视频协商字段（SDP/房间号/token）归属。

在 A 补齐前，本轮使用联调壳模拟流程，不更改后端语义。
