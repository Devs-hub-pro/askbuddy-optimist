# Call v1 联调用例与限制说明

## 联调用例（最小）

### Case 1：语音发起成功（契约已配置）
1. 进入 `pages/messages/index`，点击“去通话联调页”
2. 模式选“语音”，填写对端用户 ID
3. 点击“发起”
4. 预期：状态 `idle -> dialing`，出现 `sessionId`

### Case 2：语音接听/挂断
1. 在已有 `sessionId` 条件下点击“接听”
2. 预期：状态 `connected`
3. 点击“挂断”
4. 预期：状态 `ended`

### Case 3：拒绝来电
1. 在已有 `sessionId` 条件下点击“拒绝”
2. 预期：状态 `rejected`

### Case 4：权限拒绝
1. 清除录音权限并重新发起语音
2. 预期：状态 `failed`，Toast 提示“麦克风权限未开启”

### Case 5：视频可选能力
1. 模式切换“视频”并发起
2. 若摄像头权限未给：提示“摄像头权限未开启”
3. 给权后可进入同样状态流转

### Case 6：A 契约缺口可见性
1. 维持 `utils/call/contract.js` RPC 映射为空
2. 发起/接听/拒绝/挂断
3. 预期：页面展示 `A_CONTRACT_GAP` 信息，且不猜 RPC 字段

## 机型/权限/后台行为限制

1. 机型差异
- iOS 与安卓在权限弹窗时机、后台挂起策略存在差异，需双端真机验证。

2. 权限限制
- 语音依赖 `scope.record`；视频额外依赖 `scope.camera`。
- 用户拒绝后需在系统设置手动开启。

3. 后台行为
- 小程序进入后台后可能被挂起，通话状态同步不保证实时。
- 不提供系统级来电 UI，需回前台处理接听流程。

4. 契约依赖
- A 未下发 Call v1 RPC 映射前，当前仅能跑端侧联调壳（本地模拟状态机）。
